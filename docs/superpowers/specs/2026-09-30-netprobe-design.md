# CQU NetProbe 设计

用户已确认 Vue 3 + Vite + Node.js 单服务，并要求直接开发。系统部署于 Prometheus 所在内网，公开浏览器只访问本服务。

## 边界
Node 原生 HTTP 服务提供静态页面与固定的只读 JSON API。仅调用 Prometheus `/api/v1/query` 和 `/api/v1/query_range`。无数据库、Push、采集、账号体系、Go 或 Nginx。Node >=22，运行时后端零第三方依赖。

## 配置契约
服务器端 JSON 配置包括楼栋目录、Prometheus URL、标签映射、六项查询（online/loss/latency/jitter/http/httpLatency）、单位换算、质量窗口查询与阈值。用户在开发过程中提供 campus_probe_* 真实样例，因此默认直接适配这些指标，并加入 lastSeen/httpCode/lossWindow/flaps 查询。质量序列联合筛选 online=1 与 lastSeen<=180秒。PromQL 由管理员指定，客户端不能提交任意表达式。指标结果须保留楼栋与探针标签，目标标签可选。暂无数据不使用伪造数据填充。

## 状态
无有限样本或样本过期为空白。所有已观测探针 online=0 为下线（红）；任一 offline、数据不完整、在线状态未知、轻度丢包为等待（黄）；明确在线且质量正常为在线（绿）；有在线探针且丢包/抖动/状态切换超过可配置阈值为波动（橙）。状态不将 exporter `up` 自动等同网络连通。查询错误独立展示；部分错误不输出绿色确认状态。HTTP 状态作为独立测量显示。

## 页面
总览按校区、楼栋群、楼栋排列，白色空状态、颜色与文字共同标识、搜索/状态/校区筛选、30秒刷新及手动刷新。详细监控包含楼栋比较表与按需展开历史。楼栋详情包括当前值、最近1/6/24小时与7天曲线、状态时间轴、探针/目标筛选与样本时间。浏览器后台停止刷新，请求可取消，路由切换保留总览筛选。

## 性能与失败
全楼栋即时查询一次批量读取每项指标，短时内存缓存与并发请求合并。历史仅对选定楼栋查询，自适应步长每条<=720点，最多200序列/指标；查询并发<=4、超时8秒、响应大小限制、LRU缓存最多100条、固定查询参数校验。不可达和未配置明确区分，无数据不判为下线。Prometheus 地址/凭据/原始错误不出现在公开 API。

## 部署与验证
Vite 静态文件与 Node 同端口提供，附多阶段非root Docker、Compose、systemd示例。核心状态、查询适配、缓存、API、错误和路径检查使用 Node 内置测试；真实连接使用本地 Prometheus 协议夹具，不向用户展示测试数据。检查桌面和移动浏览器、导航、过滤、图表交互。
